# Handoff Command

## 目的

在以下情况使用 /handoff：
- 当前会话上下文过长，质量开始下降
- 想要保留关键上下文的同时启动新会话
- 上下文窗口接近容量上限

生成一份详细的上下文摘要，可用于新会话中继续工作。

---

# 阶段 0: 验证请求

确认以下条件：
- [ ] 当前会话有需要保留的有意义的工作或上下文
- [ ] 用户确实想要创建交接摘要（而非仅仅询问相关信息）

如果会话几乎为空或没有有意义的上下文，告知用户没有实质内容需要交接。

---

# 阶段 1: 收集程序化上下文

执行以下工具收集具体数据：

```
1. mcp_session_read — 完整会话历史
2. mcp_todoread — 当前任务进度
3. Bash: git diff --stat HEAD~10..HEAD — 最近的文件变更
4. Bash: git status --porcelain — 未提交的变更
```

分析收集到的输出以了解：
- 用户要求什么（原始措辞）
- 完成了哪些工作
- 哪些任务仍未完成（包含 todo 状态）
- 做了哪些决策
- 修改或讨论了哪些文件（包含 git diff/stat + status）
- 建立了哪些模式、约束或偏好

---

# 阶段 2: 提取上下文

以第一人称视角撰写上下文摘要（"我做了..."、"我告诉你了..."）。

关注：
- 能力和行为，而非逐文件的实现细节
- 对继续工作重要的信息
- 避免过度的实现细节（变量名、存储键、常量），除非至关重要
- 用户请求（原文）必须逐字记录（不要改写）
- 明确约束必须仅为逐字原文（不要自行添加）

提取时考虑的问题：
- 我刚刚做了或实现了什么？
- 我已经给出了哪些仍然相关的指示？
- 我说过哪些文件是重要的或正在处理的？
- 我是否提供了应包含的计划或规范？
- 我已经告诉过你哪些重要信息（库、模式、约束、偏好）？
- 我发现了哪些重要的技术细节？
- 有哪些注意事项、限制或未解决的问题？

---

# 阶段 3: 格式化输出

使用以下格式生成交接摘要：

```
HANDOFF CONTEXT
===============

USER REQUESTS (AS-IS)
---------------------
- [逐字原文用户请求 - 不要改写]

GOAL
----
[一句话描述接下来应该做什么]

WORK COMPLETED
--------------
- [第一人称的要点，描述完成了什么]
- [包含相关的具体文件路径]
- [记录关键的实现决策]

CURRENT STATE
-------------
- [代码库或任务的当前状态]
- [构建/测试状态（如适用）]
- [环境或配置状态]

PENDING TASKS
-------------
- [计划但未完成的任务]
- [下一步的逻辑步骤]
- [遇到的任何阻碍或问题]
- [包含 todoread() 的当前 todo 状态]

KEY FILES
---------
- [path/to/file1] - [简要角色描述]
- [path/to/file2] - [简要角色描述]
（最多 10 个文件，按重要性优先排列）

IMPORTANT DECISIONS
-------------------
- [做出的技术决策及原因]
- [考虑过的权衡]
- [建立的模式或约定]

EXPLICIT CONSTRAINTS
--------------------
- [仅限逐字约束 - 来自用户或现有文档]
- 如无，写：无

CONTEXT FOR CONTINUATION
------------------------
- [新会话需要知道的内容以继续工作]
- [需要注意的警告或陷阱]
- [相关文档参考（如有）]
```

规则：
- 纯文本加要点符号
- 使用工作区相对路径
- 保持聚焦 - 只包含对继续工作重要的内容
- 根据复杂度选择合适的长度
- 用户请求和明确约束必须仅为逐字原文

---

# 阶段 4: 提供说明

生成摘要后，指导用户：

```
---

在新会话中继续：

1. 启动一个新的 Claude Code 会话
2. 将上面的 HANDOFF CONTEXT 作为第一条消息粘贴
3. 添加你的请求："从上面的交接上下文继续。[你的下一个任务]"

新会话将拥有无缝继续工作所需的所有上下文。
```

---

# 重要约束

- **不要**尝试以编程方式创建新会话
- **提供**一个无需访问当前会话即可工作的自包含摘要
- **使用**工作区相对文件路径
- **不要**包含敏感信息（API 密钥、凭据、秘密）
- KEY FILES 部分**不要**超过 10 个文件
- GOAL 部分保持为一句话或一小段

---

# 立即执行

开始收集程序化上下文，然后综合生成交接摘要。
