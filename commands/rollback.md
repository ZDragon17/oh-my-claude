# 回滚到上一个成功状态

当操作出错时，回滚到上一个已知的成功状态。

## 使用方式

```bash
/rollback                 # 回滚最近的失败操作
/rollback --list          # 列出可回滚的操作
/rollback --to [检查点ID] # 回滚到指定检查点
```

## 执行流程

### 步骤 1: 检测可回滚操作

分析最近的操作历史，找到可以回滚的操作：

```text
🔍 检测回滚点
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📋 最近操作:
   1. [时间] 修改 src/services/auth.ts ← 可回滚
   2. [时间] 创建 src/types/user.ts ← 可回滚
   3. [时间] 运行 npm test ← 不可回滚

💡 找到 2 个可回滚的文件操作。
```

### 步骤 2: 确认回滚范围

对于文件修改，检查是否有 git 支持：

**如果有 git**：

```text
📂 回滚方式: Git
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

检测到 Git 仓库，将使用 git checkout 回滚。

📋 将要回滚的文件:
   • src/services/auth.ts (最近修改)

⚠️ 警告: 这将丢失未提交的更改。

确认回滚？[y/N]
```

**如果没有 git**：

```text
📂 回滚方式: 备份恢复
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

⚠️ 未检测到 Git 仓库，无法自动回滚文件修改。

💡 建议:
   [1] 手动恢复文件（如有备份）
   [2] /bianque 诊断问题并修复
   [3] 继续当前操作

📝 下次建议: 使用 Git 管理代码，方便回滚。
```

### 步骤 3: 执行回滚

如果是文件操作且有 git：

```bash
# 回滚单个文件
git checkout HEAD -- [文件路径]

# 或回滚到指定提交
git checkout [commit] -- [文件路径]
```

执行后显示：

```text
✅ 回滚成功
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📋 已回滚:
   • src/services/auth.ts → 恢复到上一个版本

📊 当前状态: 文件已恢复到修改前

💡 下一步:
   • 重新尝试修改: 描述你想要的更改
   • 查看文件内容: /wukong 查看 auth.ts
   • 诊断问题: /bianque
```

### 步骤 4: 更新 TODO 状态（如果在 yishan 模式）

如果当前在愚公移山模式，回滚后需要更新 TODO：

将当前 `in_progress` 任务重置为待重试状态，在任务内容前添加 `[重试]` 标记。

## 回滚类型

| 操作类型 | 回滚方式 | 支持程度 |
| -------- | -------- | -------- |
| 文件编辑 | git checkout | ✅ 完全支持 |
| 文件创建 | git checkout / 删除文件 | ✅ 完全支持 |
| 文件删除 | git checkout | ✅ 完全支持 |
| npm install | 需要手动处理 | ⚠️ 部分支持 |
| 数据库操作 | 需要备份 | ❌ 不支持 |
| 外部 API 调用 | 不可逆 | ❌ 不支持 |

## 安全保护

1. **确认机制** - 回滚前必须确认
2. **Git 优先** - 优先使用 git 进行可追踪的回滚
3. **备份提醒** - 提醒用户备份重要更改
4. **不可逆警告** - 对于不可逆操作给出明确警告

## 响应要求

1. **检测能力** - 准确识别可以回滚的操作
2. **最小影响** - 只回滚必要的更改
3. **清晰反馈** - 明确说明回滚了什么
4. **后续指导** - 回滚后指导下一步操作
