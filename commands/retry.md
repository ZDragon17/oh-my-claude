# 智能重试

重试上一个失败的操作，支持自动调整策略。

## 使用方式

```bash
/retry                    # 重试上一个失败操作
/retry --force            # 强制重试，不做调整
/retry --with-bianque     # 先让扁鹊诊断再重试
```

## 执行流程

### 步骤 1: 检测上一个失败操作

**首先尝试读取操作历史文件** `~/.oh-my-claude/operation-history.json`：

```json
[
  {
    "tool": "Bash",
    "input": {"command": "npm test"},
    "has_error": true,
    "timestamp": "2025-01-21T10:30:00Z"
  }
]
```

如果历史文件存在且有 `has_error: true` 的条目，使用该条目作为重试目标。

**如果历史文件不存在**，回顾最近的对话历史，找到最近一次失败的操作：

- 查找包含 `❌`、`Error`、`失败`、`failed` 的消息
- 识别失败的操作类型（文件编辑、命令执行、测试等）
- 提取失败的具体上下文

### 步骤 2: 分析失败原因

分析失败的可能原因：

```text
🔍 失败分析
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📋 上次操作: [操作描述]
❌ 失败原因: [错误信息摘要]
🔢 已失败次数: [N] 次

💡 可能原因:
   • [原因 1]
   • [原因 2]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 步骤 3: 选择重试策略

根据失败次数和原因选择策略：

| 失败次数 | 策略 |
| -------- | ---- |
| 1 次 | 直接重试 |
| 2 次 | 调整参数/方法重试 |
| 3+ 次 | 建议深度诊断或换方案 |

### 步骤 4: 执行重试

**重要**: 如果失败 3 次以上，显示警告：

```text
⚠️ 重复失败警告
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

此操作已失败 [N] 次，继续重试可能无效。

💡 建议:
   [1] /bianque - 让扁鹊深度诊断问题
   [2] /zhuge - 让诸葛重新评估方案
   [3] /skip - 跳过此步骤继续
   [4] 继续重试（不推荐）

请选择操作或输入新的指令。
```

如果决定继续重试：

```text
🔄 正在重试...
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📋 操作: [操作描述]
🔧 调整: [如果有调整，说明调整内容]
⏱️ 第 [N] 次尝试

正在执行...
```

### 步骤 5: 报告结果

重试成功：

```text
✅ 重试成功！
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📋 操作: [操作描述]
🔧 成功原因: [说明什么调整起了作用]
⏱️ 尝试次数: [N] 次

继续下一步操作...
```

重试仍然失败：

```text
❌ 重试未成功
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📋 操作: [操作描述]
❌ 错误: [新的/相同的错误信息]

💡 建议:
   [1] /bianque - 深度诊断
   [2] /skip - 跳过此步骤
   [3] 描述具体问题，我来分析

请选择操作。
```

## 特殊场景

### 无失败操作时

```text
ℹ️ 没有检测到最近的失败操作

如果你遇到了问题，请：
   • 描述具体的错误信息
   • 或使用 /bianque 进行诊断
```

## 响应要求

1. **智能分析** - 不要盲目重试，先分析失败原因
2. **策略调整** - 多次失败时尝试不同方法
3. **及时止损** - 3 次以上建议换策略
4. **透明反馈** - 清楚说明重试了什么、调整了什么
