# 代码审查命令

多 Agent 协作进行全面的代码审查，包括代码规范、安全漏洞、性能问题。

## 使用方法

```bash
/review                  # 审查暂存区变更
/review staged           # 同上
/review pr 123           # 审查 PR #123
/review pr               # 审查当前分支的 PR
/review files src/       # 审查指定文件/目录
/review commit abc123    # 审查指定 commit
```

## 参数说明

用户输入: `$ARGUMENTS`

根据参数选择审查目标：

- 无参数或 `staged`: 审查 git 暂存区
- `pr [number]`: 审查 Pull Request
- `files <path>`: 审查指定文件或目录
- `commit <hash>`: 审查指定 commit 的变更

## 审查维度

| 维度 | Agent | 检查内容 |
|------|-------|----------|
| 代码规范 | 📜 魏征 | 命名规范、代码风格、最佳实践 |
| 安全审计 | 🛡️ 墨子 | 安全漏洞、敏感信息泄露、注入风险 |
| 性能检查 | ⚔️ 孙子 | 性能问题、N+1 查询、内存泄漏 |
| 测试覆盖 | ⚖️ 包拯 | 测试缺失、边界情况、错误处理 |

## 执行流程

### 步骤 1: 获取变更内容

**审查暂存区**:
```bash
git diff --cached --name-only    # 获取变更文件列表
git diff --cached                # 获取详细变更
```

**审查 PR**:
```bash
gh pr view 123 --json files,additions,deletions,body
gh pr diff 123
```

**审查指定文件**:
```bash
# 直接读取文件内容
```

### 步骤 2: 并行启动 Agent 审查

使用 Task 工具的 `run_in_background` 模式并行启动多个审查 Agent:

```
同时启动:
├─ 📜 魏征: 代码规范审查
├─ 🛡️ 墨子: 安全漏洞审查
└─ ⚔️ 孙子: 性能问题审查
```

### 步骤 3: 汇总审查结果

收集所有 Agent 的发现，按严重程度排序展示。

## 问题严重程度

| 级别 | 图标 | 说明 | 是否阻止提交 |
|------|------|------|--------------|
| 严重 | ❌ | 安全漏洞、数据丢失风险 | 是 |
| 警告 | ⚠️ | 性能问题、代码规范违反 | 建议修复 |
| 建议 | 💡 | 可改进之处 | 否 |

## Agent 审查重点

### 📜 魏征 (代码规范)

- 命名规范 (驼峰、下划线)
- 函数长度 (> 50 行警告)
- 嵌套深度 (> 3 层警告)
- 代码重复
- 类型安全 (any 使用)
- 注释质量

### 🛡️ 墨子 (安全审计)

- SQL 注入
- XSS 漏洞
- 敏感信息泄露
- 硬编码密钥
- 不安全的加密
- 权限检查缺失

### ⚔️ 孙子 (性能检查)

- N+1 查询
- 循环内 I/O
- 内存泄漏风险
- 不必要的重渲染
- 大数据处理
- 缓存缺失

### ⚖️ 包拯 (测试覆盖)

- 测试缺失
- 边界情况
- 错误处理测试
- Mock 使用
- 断言质量

## 响应要求

1. **全面审查** - 多维度并行检查
2. **问题定位** - 精确到文件和行号
3. **可操作建议** - 每个问题给出具体修复方案
4. **严重程度分级** - 帮助用户优先处理关键问题
5. **尊重用户** - 建议而非命令
