# RalPlan 迭代规划共识技能 v1.0

> 灵感来源：三顾茅庐 - 隆中对策，反复推敲
> 核心理念：规划者+架构师+审查者三方迭代，达成高质量共识

## 概述

RalPlan（迭代规划共识）是一种**多角色协作规划工作流**，
通过 Planner（规划者）、Architect（架构师）、Critic（审查者）三方迭代，
确保规划方案的完整性、可行性和高质量。

与普通规划的区别：
- **普通规划**：单一角色生成方案
- **RalPlan**：三方迭代审查，达成共识

## 核心角色

| 角色 | 对应 Agent | 职责 |
|------|-----------|------|
| 🎯 **Planner** | 诸葛 (zhuge) | 制定整体规划、目标分解、路线图 |
| 🏗️ **Architect** | 诸葛/鲁班 | 评估技术可行性、设计实现方案 |
| 🔍 **Critic** | 刘伯温 (liubowen) | 审查规划、识别风险、提出改进 |

## 使用方式

### 命令格式

```bash
# 中文命令
/gongshi 设计用户认证系统

# 英文命令
/ralplan design user authentication system

# 简写
/plan+ 实现微服务架构
```

### 规划模式

```bash
# 完整三方规划（默认）
/gongshi 实现新功能

# 快速规划（省略 Critic）
/gongshi --quick 小型功能

# 深度规划（多轮迭代）
/gongshi --deep 复杂系统设计

# 技术导向（强化 Architect）
/gongshi --tech-focus API 重构
```

### 高级选项

```bash
# 设置最大迭代次数
/gongshi --max-rounds=5

# 指定输出格式
/gongshi --format=prd      # PRD 文档
/gongshi --format=tasks    # 任务列表
/gongshi --format=roadmap  # 路线图

# 包含代码估算
/gongshi --estimate

# 保存规划结果
/gongshi --save=plan.md
```

## 与其他功能的关系

### 与诸葛规划的区别

| 特性 | 诸葛 (`/zhuge`) | RalPlan (`/gongshi`) |
|------|----------------|---------------------|
| 角色 | 单一规划者 | 三方协作 |
| 深度 | 快速规划 | 深度迭代 |
| 适用 | 中小型任务 | 复杂系统设计 |

**选择建议**：
- 快速规划 → `/zhuge`
- 复杂系统 → `/gongshi`

### 与愚公移山的集成

```bash
# 先用 RalPlan 规划，再用愚公执行
/gongshi 设计微服务架构
/yishan 按照规划实现
```

### 与刘伯温的协作

```bash
# RalPlan 自动调用刘伯温作为 Critic
# 或单独使用刘伯温审查现有方案
/liubowen 审查这个设计方案
```

## 最佳实践

1. **明确目标**: 输入清晰的需求描述
2. **提供上下文**: 说明项目背景和约束
3. **迭代改进**: 根据 Critic 反馈优化
4. **保存结果**: 使用 `--save` 保存规划文档
5. **跟踪执行**: 规划完成后用愚公模式执行
