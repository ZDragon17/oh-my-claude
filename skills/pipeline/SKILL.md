# Pipeline 流水线模式技能 v1.0

> 灵感来源：工业流水线，福特 T 型车革命
> 核心理念：前一步的输出是后一步的输入，环环相扣

## 概述

Pipeline（流水线）模式是一种**顺序链执行**模式，让多个 Agent 按照预定义的顺序依次执行，
每个 Agent 的输出会作为下一个 Agent 的输入上下文。

与其他模式的区别：
- **Ultrapilot（超级模式）**：并行执行，同时启动多个 Agent
- **Swarm（蜂群模式）**：协作执行，多个同类 Agent 共享任务池
- **Pipeline（流水线）**：顺序执行，Agent 之间有数据依赖

## 适用场景

| 场景 | 流水线配置 | 说明 |
|------|-----------|------|
| Bug 修复 | 扁鹊 → 鲁班 → 包拯 | 诊断 → 修复 → 测试 |
| 功能开发 | 李白 → 诸葛 → 鲁班 → 包拯 | 需求 → 设计 → 实现 → 测试 |
| 代码重构 | 悟空 → 诸葛 → 鲁班 → 魏征 | 探索 → 规划 → 实现 → 审查 |
| 安全审计 | 墨子 → 扁鹊 → 鲁班 | 审计 → 诊断 → 修复 |
| 性能优化 | 孙子 → 诸葛 → 鲁班 | 分析 → 规划 → 优化 |

## 使用方式

### 命令格式

```bash
# 基本格式：用箭头连接 Agent
/liushuixian 悟空 → 诸葛 → 鲁班 分析并重构认证模块

# 英文格式
/pipeline explore → architect → implement refactor auth module

# 简写格式（用 > 代替 →）
/pipeline wukong > zhuge > luban 重构认证模块
```

### 预设流水线

| 预设名称 | Agent 链 | 用途 |
|---------|----------|------|
| `bugfix` | 扁鹊 → 鲁班 → 包拯 | Bug 修复标准流程 |
| `feature` | 李白 → 诸葛 → 鲁班 → 包拯 | 功能开发完整流程 |
| `refactor` | 悟空 → 诸葛 → 鲁班 → 魏征 | 重构标准流程 |
| `security` | 墨子 → 扁鹊 → 鲁班 | 安全修复流程 |
| `perf` | 孙子 → 诸葛 → 鲁班 | 性能优化流程 |

```bash
# 使用预设流水线
/liushuixian bugfix 修复登录超时问题
/pipeline feature 实现用户头像上传功能
```

## 执行流程

```
┌─────────────────────────────────────────────────────────────┐
│                    Pipeline 流水线模式                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  用户输入: "重构认证模块"                                    │
│      ↓                                                      │
│  ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐  │
│  │  悟空   │ →  │  诸葛   │ →  │  鲁班   │ →  │  魏征   │  │
│  │ (探索)  │    │ (规划)  │    │ (实现)  │    │ (审查)  │  │
│  └─────────┘    └─────────┘    └─────────┘    └─────────┘  │
│      ↓              ↓              ↓              ↓        │
│  [代码结构]    [重构方案]    [实现代码]    [审查报告]       │
│                                                             │
│  每一步的输出都会作为下一步的上下文输入                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 数据传递机制

### 上下文传递

每个 Agent 执行完成后，其输出会被结构化保存：

```markdown
## 流水线上下文

### Stage 1: 悟空 (探索) - 已完成
**任务**: 探索认证模块结构
**输出**:
- 发现 3 个核心文件: auth.ts, session.ts, token.ts
- 识别出 2 个潜在问题: 循环依赖、过度耦合
- 建议重构方向: 分离关注点

### Stage 2: 诸葛 (规划) - 进行中
**任务**: 基于悟空的发现制定重构方案
**输入上下文**: [Stage 1 输出]
...
```

### 中断与恢复

```bash
# 查看当前流水线状态
/pipeline status

# 从某个阶段重新开始
/pipeline resume stage:2

# 跳过当前阶段
/pipeline skip

# 取消流水线
/pipeline cancel
```

## 高级用法

### 条件分支

```bash
# 根据上一步结果决定下一步
/pipeline 孙子 → [性能问题?鲁班:完成] 分析接口性能
```

### 并行子流水线

```bash
# 某个阶段可以并行执行多个 Agent
/pipeline 悟空 → (诸葛 + 墨子) → 鲁班
# 先探索，然后同时进行架构规划和安全评估，最后实现
```

### 自定义流水线模板

在 `.claude/pipelines/` 创建自定义模板：

```yaml
# .claude/pipelines/my-feature.yaml
name: my-feature
description: 我的功能开发流程
stages:
  - agent: libai
    task: 分析需求，输出用户故事
  - agent: zhuge
    task: 设计技术方案
  - agent: luban
    task: 实现功能
  - agent: baozheng
    task: 编写测试
  - agent: weizheng
    task: 代码审查
```

```bash
# 使用自定义模板
/pipeline template:my-feature 实现购物车功能
```

## 与其他模式组合

```bash
# 流水线中使用低成本模型
/pipeline --eco 悟空 → 诸葛 → 鲁班
```

### Pipeline + Ralph（持久流水线）

```bash
# 流水线失败时自动重试
/pipeline --persistent 扁鹊 → 鲁班 → 包拯
```

## 最佳实践

### 1. 选择合适的 Agent 顺序

```
探索/分析 → 规划/设计 → 实现 → 验证/审查
   悟空        诸葛       鲁班     包拯/魏征
```

### 2. 每个阶段明确任务

```bash
# 好：每个阶段任务明确
/pipeline 悟空:找到所有API路由 → 诸葛:设计统一错误处理 → 鲁班:实现

# 不好：任务模糊
/pipeline 悟空 → 诸葛 → 鲁班 改进代码
```

### 3. 合理控制流水线长度

- 推荐：2-4 个阶段
- 最多：6 个阶段
- 超过 6 个阶段建议拆分为多个流水线
