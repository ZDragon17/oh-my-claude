# 智能上下文管理 (Context Management)

监控和优化上下文使用，预防长会话崩溃。

## 核心理念

> 上下文如同内存，善用则畅通无阻，滥用则捉襟见肘。
> 智能管理上下文，让长任务持续稳定运行。

## 功能概述

### 1. 状态监控 (/context status)

实时显示上下文使用情况：
- 使用率百分比
- Token 估算值
- 组成分析（对话/代码/系统提示）
- 健康状态和建议

### 2. 智能压缩 (/context compact)

压缩对话历史释放空间：
- 识别可压缩内容
- 保留关键信息
- 生成压缩摘要
- 提供恢复方法

### 3. 缓存清理 (/context clean)

清理临时数据和缓存：
- 过期上下文缓存
- 临时文件引用
- 旧压缩记录

### 4. 信息导出 (/context export)

导出重要信息供后续使用：
- TODO 列表
- 技术决策记录
- 进度摘要
- 关键代码引用

## 使用率等级

| 使用率 | 状态 | 图标 | 建议操作 |
|--------|------|------|----------|
| 0-50% | 充裕 | 🟢 | 可自由工作 |
| 50-70% | 正常 | 🟢 | 关注变化 |
| 70-85% | 注意 | ⚠️ | 建议压缩 |
| 85-95% | 警告 | 🟠 | 尽快压缩 |
| 95%+ | 紧急 | 🚨 | 立即处理 |

## Token 估算方法

基于字符比例估算 Token 数量：

| 内容类型 | 字符/Token |
|----------|------------|
| 中文字符 | ~1.5 |
| 英文字符 | ~4 |
| 代码 | ~3 |

```
估算公式:
tokens ≈ 中文字符数/1.5 + 英文字符数/4 + 代码字符数/3
```

## 进度条生成

```
宽度: 30 字符
满格: █
空格: ░

填充数 = floor(使用率% / 100 * 30)
空白数 = 30 - 填充数

示例:

```

## 压缩策略

### 1. 摘要压缩 (Summary)

提取对话要点，生成简洁摘要：
- 适用于探索性对话
- 保留关键结论
- 压缩率高

### 2. 要点压缩 (Keypoints)

保留决策点和关键代码引用：
- 适用于技术决策讨论
- 保留上下文链
- 可回溯性好

### 3. 层次压缩 (Hierarchical)

分层归档，按重要性保留：
- 适用于长期项目
- 近期详细，远期概要
- 平衡压缩率和信息量

## 可压缩内容

| 类型 | 描述 | 优先级 |
|------|------|--------|
| 早期探索对话 | 初期的代码搜索和阅读 | 高 |
| 已完成任务细节 | 已解决问题的详细过程 | 高 |
| 重复代码展示 | 多次显示的相同代码 | 高 |
| 调试输出 | 临时的日志和调试信息 | 高 |
| 构建输出 | 成功的编译/测试输出 | 中 |
| 探索性讨论 | 未采用的方案讨论 | 中 |

## 必须保留的内容

| 类型 | 原因 |
|------|------|
| 当前 TODO 列表 | 任务追踪必需 |
| 进行中任务上下文 | 继续工作必需 |
| 关键技术决策 | 避免重复讨论 |
| 最近 N 轮对话 | 连贯性需要 |
| 错误和解决方案 | 避免重复犯错 |

|------|----------|------|
| 💡 提示 | 70% | 显示简短提示 |
| ⚠️ 警告 | 85% | 弹出警告信息 |

## 最佳实践

### 1. 定期检查

在长会话中定期执行 `/context` 查看状态。

### 2. 主动压缩

不要等到紧急状态才压缩，70% 时就应考虑。

### 3. 及时导出

重要信息及时导出，避免丢失。

### 4. 分阶段保存

大任务分阶段保存会话，避免一次性消耗过多上下文。

### 5. 简化探索

探索阶段使用 Agent（如 @wukong）在后台执行，减少主上下文消耗。
