# 代码审查技能 (Code Review)

多 Agent 协作进行全面的代码审查，确保代码质量和安全性。

## 核心理念

> 代码审查是质量的第一道防线。
> 多维度审查，不遗漏任何问题。

## 审查维度

### 📜 魏征 - 代码规范审查

| 检查项 | 阈值 | 严重程度 |
|--------|------|----------|
| 函数长度 | > 50 行 | ⚠️ 警告 |
| 嵌套深度 | > 3 层 | ⚠️ 警告 |
| 文件长度 | > 300 行 | 💡 建议 |
| 命名规范 | 不符合约定 | ⚠️ 警告 |
| any 使用 | 存在 | ⚠️ 警告 |
| 代码重复 | > 10 行相同 | ⚠️ 警告 |

### 🛡️ 墨子 - 安全审计

| 检查项 | 说明 | 严重程度 |
|--------|------|----------|
| SQL 注入 | 字符串拼接 SQL | ❌ 严重 |
| XSS 漏洞 | 未转义用户输入 | ❌ 严重 |
| 敏感信息 | 密码、密钥泄露 | ❌ 严重 |
| 硬编码密钥 | API Key 等 | ❌ 严重 |
| 不安全加密 | MD5、SHA1 密码 | ⚠️ 警告 |
| 权限缺失 | 未检查权限 | ⚠️ 警告 |

### ⚔️ 孙子 - 性能检查

| 检查项 | 说明 | 严重程度 |
|--------|------|----------|
| N+1 查询 | 循环内数据库查询 | ⚠️ 警告 |
| 循环内 I/O | 循环内文件/网络操作 | ⚠️ 警告 |
| 内存泄漏 | 未清理的订阅/定时器 | ⚠️ 警告 |
| 重复渲染 | React 不必要渲染 | 💡 建议 |
| 大数据处理 | 无分页/流式处理 | ⚠️ 警告 |
| 缓存缺失 | 重复计算无缓存 | 💡 建议 |

### ⚖️ 包拯 - 测试覆盖

| 检查项 | 说明 | 严重程度 |
|--------|------|----------|
| 测试缺失 | 新功能无测试 | ⚠️ 警告 |
| 边界情况 | 未测试边界条件 | 💡 建议 |
| 错误处理 | 未测试异常路径 | 💡 建议 |
| Mock 过度 | 过多 Mock 降低价值 | 💡 建议 |
| 断言缺失 | 测试无有效断言 | ⚠️ 警告 |

## 审查流程

```
┌─────────────────────────────────────────────────────────────┐
│  1. 获取变更内容                                            │
│     ├─ git diff --cached (暂存区)                          │
│     ├─ gh pr diff (PR)                                     │
│     └─ 直接读取文件                                         │
├─────────────────────────────────────────────────────────────┤
│  2. 并行启动审查 Agent                                      │
│     ├─ 📜 魏征: 代码规范                                    │
│     ├─ 🛡️ 墨子: 安全审计                                    │
│     ├─ ⚔️ 孙子: 性能检查                                    │
│     └─ ⚖️ 包拯: 测试覆盖                                    │
├─────────────────────────────────────────────────────────────┤
│  3. 汇总审查结果                                            │
│     ├─ 按严重程度排序                                       │
│     ├─ 去重合并相似问题                                     │
│     └─ 生成审查报告                                         │
├─────────────────────────────────────────────────────────────┤
│  4. 给出审查结论                                            │
│     ├─ ✅ 通过: 无严重问题                                  │
│     ├─ ⚠️ 需修改: 有警告                                    │
│     └─ ❌ 不通过: 有严重问题                                │
└─────────────────────────────────────────────────────────────┘
```

## 问题格式

每个问题包含：

```
[严重程度] [维度] 文件路径:行号
问题描述
```代码片段```
建议: 具体修复方案
```

示例：

```
❌ [🛡️ 安全] src/auth/login.ts:45
密码明文记录到日志
```typescript
console.log(`Login: ${email}, ${password}`);  // ❌
```
建议: 移除密码日志，仅记录邮箱
```

## 审查结论判定

| 条件 | 结论 | 图标 |
|------|------|------|
| 无严重和警告 | 可以提交 | ✅ |
| 仅有建议 | 可以提交 | ✅ |
| 有警告无严重 | 建议修复后提交 | ⚠️ |
| 有严重问题 | 不建议提交 | ❌ |

## 使用场景

### 提交前审查

```bash
git add .
/review staged
# 发现问题 → 修复 → 重新 /review
# 通过 → /git commit
```

### PR 审查

```bash
/review pr 123
# 生成审查报告
# 可自动添加 PR 评论
```

### 定向审查

```bash
/review files src/auth/
# 仅审查指定目录
```

## 与其他功能集成

### 与 /git 集成

可在 `/git commit` 前自动触发审查：

```bash
/git commit --review
# 等同于 /review staged && /git commit
```

### 与 /parallel 集成

审查 Agent 可并行执行：

```bash
# 内部自动使用
/parallel @weizheng @mozi @sunzi @baozheng 审查暂存区代码
```

### 与 /yishan 集成

愚公移山流程中可包含代码审查步骤：

```
TODO 列表:
1. ✅ 实现功能
2. ✅ 编写测试
3. 🔄 代码审查 ← /review
4. ⏳ 提交代码
```

## 自定义配置

可在 `.oh-my-claude/config.json` 中自定义阈值：

```json
{
  "review": {
    "thresholds": {
      "maxFunctionLines": 100,
      "maxNestingDepth": 4
    },
    "skipDimensions": ["testing"],
    "autoReviewOnCommit": true
  }
}
```

## 最佳实践

1. **提交前必审** - 养成 `/review` 后再 commit 的习惯
2. **关注严重问题** - 严重问题必须修复
3. **警告酌情处理** - 根据上下文判断是否修复
4. **建议长期改进** - 记录建议，后续逐步优化
