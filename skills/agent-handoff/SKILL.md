# Agent 交接系统 (Agent Handoff)

解决问题：多 Agent 协作时上下文传递依赖自然语言，信息可能丢失。

## 核心机制

### 1. 交接报告格式

当一个 Agent 完成工作并需要传递给下一个 Agent 时，**必须**生成标准化交接报告：

```text
📦 Agent 交接报告
═══════════════════════════════════════════════════

🔄 交接: [源 Agent] → [目标 Agent]
⏰ 时间: [时间戳]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ 已完成工作:
• [具体完成的任务 1]
• [具体完成的任务 2]
• [具体完成的任务 3]

📁 产出文件:
• [文件路径 1] - [简要说明]
• [文件路径 2] - [简要说明]

📋 关键决策:
• [决策 1]: [原因]
• [决策 2]: [原因]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

📋 下一步任务:
• [具体任务 1]
• [具体任务 2]

⚠️ 注意事项:
• [注意点 1]
• [注意点 2]

💡 建议:
• [建议 1]
• [建议 2]

═══════════════════════════════════════════════════
```

### 3. 触发条件

以下情况**必须**生成交接报告：

| 场景 | 触发 |
|------|------|
| Agent 切换 | 愚公调用新的子 Agent 时 |
| 阶段完成 | 探索/设计/实现/测试阶段结束时 |
| 任务传递 | 一个 Agent 的输出是另一个的输入时 |
| 显式请求 | 用户输入 `/handoff` 时 |

### 5. 使用方式

#### 自动触发

愚公在调用子 Agent 时会自动生成交接报告：

```
Task(subagent_type="general", prompt="
作为鲁班（精工巧匠），请根据以下交接信息实现功能：

[自动插入交接报告]

请严格按照交接报告中的任务列表执行。
")
```

#### 手动触发

用户可以随时查看或生成交接报告：

```bash
/handoff          # 显示最近的交接报告
/handoff save     # 保存当前上下文到交接文件
/handoff show     # 显示完整交接历史
```

## 配置

通过 `skill.json` 配置：

```json
{
  "agent-handoff": {
    "auto_save": true,
    "save_path": ".claude/context/",
    "retention_days": 7,
    "verbose_mode": false
  }
}
```

## 注意事项

1. **保持简洁**: 交接报告应聚焦关键信息，避免冗余
2. **具体可执行**: 任务列表必须是具体可执行的步骤
3. **上下文完整**: 确保接收 Agent 有足够信息独立工作
4. **文件追踪**: 始终包含相关文件路径便于查阅
