# 并行 Agent 执行 (Parallel Execution)

同时调度多个专业 Agent，并行处理独立任务。

## 核心理念

> 兵贵神速，分进合击。
> 多路并进，效率倍增。

## 适用场景

### ✅ 适合并行的任务

| 场景 | 推荐 Agent 组合 | 理由 |
|------|----------------|------|
| 全面代码分析 | @wukong + @mozi + @sunzi | 探索、安全、性能三维度 |
| 质量检查 | @bianque + @baozheng + @weizheng | Bug、测试、代码审查 |
| 技术调研 | @wukong + @simaqian | 探索代码 + 整理文档 |
| 架构评审 | @zhuge + @cangjie | 整体架构 + 数据设计 |

### ❌ 不适合并行的任务

| 场景 | 原因 |
|------|------|
| 有依赖关系的实现任务 | 后续任务依赖前置结果 |
| 需要上一步输出的任务 | 无法提前知道输入 |
| 文件修改类任务 | 可能产生冲突 |
| 需要实时交互的任务 | 并行执行无法交互 |

## 命令格式

### 多行格式（推荐）

```bash
/parallel
  @wukong 探索认证模块的代码结构
  @mozi 审计认证模块的安全漏洞
  @baozheng 检查认证模块的测试覆盖率
```

### 单行格式

```bash
/parallel @wukong @mozi @baozheng 全面分析认证模块
```

单行格式中，共享任务描述会分配给所有 Agent。

## 执行流程

```
┌─────────────────────────────────────────────┐
│  1. 解析命令 - 识别 @agent 和任务描述        │
├─────────────────────────────────────────────┤
│  2. 验证 Agent - 检查是否为有效 Agent        │
├─────────────────────────────────────────────┤
│  3. 检查兼容性 - 警告不推荐的组合            │
├─────────────────────────────────────────────┤
│  4. 创建 TODO - 为每个 Agent 创建任务        │
├─────────────────────────────────────────────┤
│  5. 并行启动 - 使用 run_in_background        │
├─────────────────────────────────────────────┤
│  6. 监控状态 - 实时显示执行进度              │
├─────────────────────────────────────────────┤
│  7. 汇总结果 - 合并所有 Agent 的发现         │
└─────────────────────────────────────────────┘
```

## 最佳实践

### 1. 选择合适的 Agent 组合

- 同组 Agent 可安全并行
- 跨组需注意依赖关系
- 避免实现类 Agent 并行

### 2. 任务描述要清晰

```bash
# ✅ 好的描述
@wukong 探索 src/auth 目录下的认证逻辑，重点关注 JWT 处理

# ❌ 模糊的描述
@wukong 看看代码
```

### 3. 控制并行数量

- 推荐最多 3 个 Agent 并行
- 过多并行可能导致结果混乱

### 4. 结果后续处理

并行分析完成后：
1. 阅读各 Agent 的汇总报告
2. 根据建议创建 TODO 列表
3. 使用 `/yishan` 执行修复/优化

## 与其他技能集成

### 与愚公移山集成

并行任务完成后，可直接启动愚公执行后续任务：

```bash
# 并行分析
/parallel @wukong @mozi @baozheng 分析认证模块

# 根据分析结果执行
/yishan 根据上述分析，修复安全问题并补充测试
```

### 与进度面板集成

- 并行任务自动显示在进度面板
- 可使用 `/progress` 查看实时状态

### 与会话管理集成

- 并行任务结果可保存到会话
- 便于后续恢复和继续

## 限制说明

| 限制 | 值 | 原因 |
|------|----|------|
| 最大并行数 | 3 | 保证结果可管理 |
| 实现类 Agent | 不建议并行 | 可能文件冲突 |
| 依赖任务 | 不支持 | 需顺序执行 |

## 技术实现

使用 Task 工具的 `run_in_background: true` 参数：

```
对于每个 Agent:
  Task(
    subagent_type=agent.subagentType,
    description="[并行任务] " + agent.name,
    prompt=agent.task,
    run_in_background=true
  )
```

所有 Agent 真正并行启动，独立执行，最后汇总结果。
