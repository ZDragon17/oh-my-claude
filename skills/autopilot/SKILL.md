# Autopilot 自动驾驶模式技能 v1.0

> 灵感来源：神行太保戴宗 - 《水浒传》中以神行法闻名，日行八百里
> 核心理念：从想法到代码，全程自动，无需干预

## 概述

Autopilot（自动驾驶）模式是一种**完全自主**的执行模式，只需描述你想要什么，
系统会自动完成从需求分析到代码实现的全部流程。

与其他模式的区别：
- **Yishan（愚公移山）**：需要用户确认关键决策
- **Ultrapilot（超级模式）**：并行但仍需监督
- **Autopilot（自动驾驶）**：完全自主，从想法到成品

## 核心特性

| 特性 | 说明 |
|------|------|
| 🎯 零干预 | 描述目标后无需任何干预 |
| 🤖 智能决策 | 自动选择最佳实现方案 |
| 🔄 自动修复 | 遇到问题自动诊断修复 |
| ✅ 自动验证 | 完成后自动测试验证 |
| 📊 完整报告 | 输出详细的执行报告 |

## 智能决策机制

### 技术栈自动选择

Autopilot 会根据项目类型自动选择最佳技术栈：

| 项目类型 | 自动选择 |
|---------|---------|
| REST API | Node.js + Express 或项目已有框架 |
| 前端应用 | React/Vue 或项目已有框架 |
| CLI 工具 | Node.js + Commander 或 Python + Click |
| 数据处理 | Python + Pandas 或 Node.js |
| 全栈应用 | Next.js 或 Nuxt.js |

如果项目已有技术栈，会自动适配现有架构。

### 错误自动修复

```
遇到错误 → 扁鹊诊断 → 自动修复 → 重新验证
    ↑                              ↓
    └────────── 循环直到成功 ←────────┘
```

最多重试 3 次，超过后报告问题并提供手动修复建议。

## 配置选项

```bash
# 快速模式：跳过测试和审查
/shenxing --fast 实现一个简单的工具函数

# 严格模式：完整测试和安全审查
/shenxing --strict 实现支付模块

# 指定技术栈
/shenxing --tech=fastapi 构建 REST API

# 干燥运行：只生成计划不执行
/shenxing --dry-run 构建博客系统
```

## 最佳实践

### 1. 清晰描述目标

```bash
# 好：目标明确
/shenxing 构建一个 REST API，包含用户注册、登录、CRUD 操作

# 不好：目标模糊
/shenxing 做一个后端
```

### 2. 提供约束条件

```bash
# 好：有技术约束
/shenxing 使用 TypeScript 和 Prisma 构建用户管理 API

# 也可以：让系统自动选择
/shenxing 构建用户管理 API
```

### 3. 适合的项目规模

- ✅ 适合：单个功能模块、小型应用、原型开发
- ⚠️ 谨慎：大型系统、关键业务逻辑
- ❌ 不适合：需要人工审核的敏感操作

## 安全保障

1. **不会删除现有代码** - 只添加新文件或扩展现有文件
2. **不会修改配置文件** - 敏感配置需要人工确认
3. **不会执行危险命令** - 如 `rm -rf`、数据库删除等
4. **Git 安全** - 不会自动提交或推送
