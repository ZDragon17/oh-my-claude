# UltraQA 自主 QA 循环技能 v1.0

> 灵感来源：神农 - 尝百草，不惧试错
> 核心理念：自动化测试循环，直到所有测试通过

## 概述

UltraQA（自主 QA 循环）是一种**自动化质量保障工作流**，
通过持续的测试-分析-修复循环，确保代码质量达标。

与普通测试的区别：
- **普通测试**：运行一次，报告结果
- **UltraQA**：持续循环，直到全部通过

## 使用方式

### 命令格式

```bash
# 中文命令
/ceshi 运行所有测试直到通过

# 英文命令
/ultraqa run all tests until pass

# 简写
/qa 持续测试
```

### 测试模式

```bash
# 全量测试（默认）
/ceshi

# 增量测试（只测试改动相关）
/ceshi --incremental

# 指定测试范围
/ceshi --path=src/auth

# 指定测试类型
/ceshi --type=unit        # 单元测试
/ceshi --type=integration # 集成测试
/ceshi --type=e2e         # 端到端测试
```

### 高级选项

```bash
# 设置最大循环次数
/ceshi --max-cycles=5

# 设置单次超时
/ceshi --timeout=300

# 快速失败模式（第一个失败就停止）
/ceshi --fail-fast

# 覆盖率阈值
/ceshi --coverage=80

# 静默模式
/ceshi --quiet

# 详细输出
/ceshi --verbose
```

## 失败分析策略

### 失败分类

| 类型 | 描述 | 处理策略 |
|------|------|----------|
| 🔴 断言失败 | 预期结果不匹配 | 检查业务逻辑 |
| 🟠 超时失败 | 执行时间超限 | 优化性能/调整超时 |
| 🟡 环境失败 | 依赖/配置问题 | 修复环境配置 |
| 🔵 编译失败 | 代码无法编译 | 修复语法/类型错误 |
| ⚪ 跳过测试 | 被标记跳过 | 评估是否需要启用 |

### 修复优先级

1. **编译错误** - 阻塞所有测试
2. **环境问题** - 影响多个测试
3. **关键路径失败** - 核心功能
4. **普通断言失败** - 业务逻辑
5. **性能问题** - 超时相关

## 注意事项

1. **资源消耗**: 多次循环会消耗较多时间和计算资源
2. **死循环风险**: 设置合理的 `--max-cycles` 防止无限循环
3. **环境隔离**: 建议在隔离环境中运行，避免影响生产数据
4. **增量优先**: 大型项目建议使用 `--incremental` 模式
