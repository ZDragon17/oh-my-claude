# 工作流模板系统

当用户需要执行多步骤任务时，提供预设工作流程和自定义工作流支持。

## 触发条件

1. 用户输入 `/workflow` 命令
2. 用户输入 `/wf`、`/流程`、`/工作流`、`/大禹`
3. 用户描述包含"工作流"、"流程"、"完整流程"等关键词

## 核心功能

### 1. 内置工作流

提供以下预设工作流：

| 工作流 | 用途 | 阶段 |
|--------|------|------|
| `feature` | 新功能开发 | 需求分析 → 架构设计 → 实现 → 测试 → 审查 |
| `bugfix` | Bug 修复 | 诊断 → 定位 → 修复 → 测试 |
| `refactor` | 代码重构 | 探索 → 分析 → 重构 → 审查 → 测试 |
| `security` | 安全审计 | 扫描 → 审计 → 建议 → 修复 |
| `review` | 代码审查 | 并行审查 → 汇总报告 |
| `deploy` | 部署流程 | 检查 → 测试 → 构建 → 部署 → 验证 |

### 2. 执行逻辑

当用户执行 `/workflow run <name> <task>` 时：

```
1. 加载工作流定义
2. 创建 TODO 列表（每个阶段一个 TODO）
3. 按顺序执行各阶段：
   a. 标记当前阶段 in_progress
   b. 调用对应 Agent
   c. 等待 Agent 完成
   d. 标记阶段 completed
   e. 进入下一阶段
4. 所有阶段完成后，生成执行报告
```

### 3. 阶段间数据传递

每个阶段完成后，将关键输出传递给下一阶段：

```json
{
  "stage_outputs": {
    "需求分析": {
      "user_stories": [...],
      "acceptance_criteria": [...]
    },
    "架构设计": {
      "technical_approach": "...",
      "risk_assessment": "..."
    }
  }
}
```

## 执行规则

### 阶段类型

1. **必选阶段** (`optional: false`)
   - 必须执行，不能跳过
   - 失败时整个工作流暂停

2. **可选阶段** (`optional: true`)
   - 可以跳过
   - 根据条件自动判断是否执行

3. **并行阶段** (`parallel: true`)
   - 多个 Agent 同时执行
   - 等待所有并行任务完成后继续

### 失败处理

1. **自动重试**：可配置的自动重试次数
2. **手动干预**：提示用户选择重试/跳过/取消
3. **回滚机制**：支持回滚到上一个成功阶段

### 超时处理

每个阶段有默认超时时间：
- 简单阶段：5 分钟
- 复杂阶段：30 分钟
- 可在配置中自定义

## 自定义工作流

### 保存工作流

用户可将当前会话保存为工作流：

```
/workflow save my-flow
```

系统会：
1. 分析会话中的 Agent 调用顺序
2. 提取每个阶段的 prompt 模板
3. 生成工作流配置文件

### 工作流存储

```
~/.oh-my-claude/workflows/
├── builtin/           # 内置工作流（只读）
│   ├── feature.json
│   └── bugfix.json
└── custom/            # 用户自定义
    └── my-flow.json
```

## 与其他功能集成

### 与 /progress 集成

工作流执行时自动更新进度面板。

### 与 /session 集成

工作流状态自动保存，支持断点恢复。

### 与 /parallel 集成

并行阶段自动使用并行执行能力。
