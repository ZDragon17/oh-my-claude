# 智能重构技能 (Smart Refactor)

安全、系统化的代码重构，支持智能分析和建议。

## 核心理念

> 重构是改善代码设计而不改变行为。
> 安全第一，小步前进。

## 黄金规则

1. **先理解，后重构** - 不要盲目重构
2. **小步前进** - 每次只做一个小改动
3. **持续验证** - 每步都运行测试
4. **保持功能** - 重构不改变行为

> **特别重要**: Bug 修复时不要重构，重构时不要修复 Bug

## 重构类型

### 🏷️ 重命名 (Rename)

改善命名，提高可读性。

```bash
/refactor rename getUserById -> findUserById
```

### 📦 提取 (Extract)

提取函数、类、模块。

```bash
/refactor extract calculateTotal from OrderService.processOrder
```

### 📁 移动 (Move)

改善代码组织。

```bash
/refactor move utils/helpers.ts -> lib/helpers/
```

### 🧹 简化 (Simplify)

减少复杂度，召唤老子进行简化。

```bash
/refactor simplify src/components/Dashboard.tsx
```

### 🔍 智能建议 (Suggest)

自动分析代码，推荐重构机会。

```bash
/refactor suggest src/services/
/refactor suggest --file src/components/Dashboard.tsx
/refactor suggest --all
```

## 分析维度

| 维度 | 图标 | 检测内容 | 阈值 |
|------|------|----------|------|
| 长度 | 📏 | 函数/文件过长 | 函数 > 50 行，文件 > 300 行 |
| 重复 | 🔄 | 相似代码块 | > 10 行相同 |
| 复杂度 | 🌀 | 圈复杂度、嵌套深度 | 圈复杂度 > 10，嵌套 > 3 |
| 命名 | 🏷️ | 不符合规范、含义模糊 | - |
| 耦合 | 📦 | 过多依赖、循环导入 | - |
| 可测试性 | 🧪 | 难以单元测试 | - |

## 严重程度

| 级别 | 图标 | 说明 |
|------|------|------|
| 严重 | ❌ | 必须修复的问题 |
| 警告 | ⚠️ | 建议修复的问题 |
| 建议 | 💡 | 可选优化 |

## 验证清单

每次重构后验证：

- [ ] lsp_diagnostics 无新错误
- [ ] 所有测试通过
- [ ] 行为没有改变
- [ ] 代码质量提升
- [ ] 没有引入新的依赖问题

## 并行分析

对于大型重构，使用并行 Agent 分析：

1. **Agent 1**: 找到重构目标的所有出现位置
2. **Agent 2**: 找到所有依赖关系
3. **Agent 3**: 找到代码库中的相似模式
4. **Agent 4**: 检查测试覆盖情况

## 常见重构场景

| 场景 | 建议操作 |
|------|----------|
| 函数太长 | 提取子函数 |
| 重复代码 | 提取公共函数/组件 |
| 命名不清 | 重命名 |
| 文件太大 | 拆分模块 |
| 依赖混乱 | 重组导入、提取接口 |
| 嵌套太深 | 提前返回、提取函数 |
| 魔术数字 | 提取常量 |

## 与老子集成

简化重构可调用老子（简洁之道大师）：

```
/refactor simplify → 调用 Task(subagent_type="general", prompt="作为老子...")
```

老子的简化能力：
- 消除重复
- 简化条件
- 减少嵌套
- 提高可读性

## 最佳实践

1. **测试先行** - 确保有足够的测试覆盖
2. **版本控制** - 频繁提交，便于回滚
3. **代码审查** - 重构后让他人审查
4. **文档更新** - 同步更新相关文档
5. **渐进式** - 大重构分多次完成
