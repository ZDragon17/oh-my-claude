# oh-my-claude 用户功能期望清单

> 从用户视角出发，整理的功能改进和新增建议

## 📊 优先级说明

- 🔴 **P0 - 核心需求**：显著提升核心体验，建议优先实现
- 🟠 **P1 - 重要功能**：提升竞争力，中期目标
- 🟡 **P2 - 增强功能**：锦上添花，长期规划
- 🟢 **P3 - 探索性**：创新方向，可作为实验

---

## 🔴 P0 - 核心需求

### 1. 多模型编排支持

**现状问题**：目前只支持 Claude，无法利用其他模型的优势。

**期望功能**：
```yaml
# 期望的配置方式
models:
  default: claude-sonnet-4
  agents:
    wukong: grok-3        # 快速探索用 Grok
    gukaizhi: gemini-2    # UI 设计用 Gemini（多模态强）
    zhuge: gpt-5          # 架构设计用 GPT（逻辑强）
    bianque: claude-opus  # 调试用 Opus（细致）
```

**用户价值**：
- 成本优化：简单任务用便宜模型
- 能力最大化：每个任务用最擅长的模型
- 灵活性：不被单一供应商锁定

### 2. 真正的并行 Agent 执行

**现状问题**：`/team` 命令是串行调用，不是真正并行。

**期望功能**：
```bash
# 期望的使用方式
/team parallel
  @wukong 探索认证模块
  @mozi 审计安全配置
  @baozheng 检查测试覆盖率
# 三个任务真正同时执行，最后汇总结果
```

**技术实现建议**：
- 使用 Claude Code 的 `background_task` 能力
- 实现任务依赖图，支持 DAG 调度
- 提供实时进度汇总面板

### 3. 智能上下文管理

**现状问题**：长对话容易触及上下文限制，手动管理繁琐。

**期望功能**：
- **自动摘要**：对话过长时自动压缩历史
- **选择性遗忘**：可以标记"这部分不重要，可以遗忘"
- **上下文预算**：显示当前上下文使用量和预警

```
┌─────────────────────────────────────┐
│ 📊 上下文使用: ████████░░ 78%       │
│ 预计还能: ~15轮对话                 │
│ [压缩历史] [清理缓存] [查看详情]    │
└─────────────────────────────────────┘
```

### 4. 会话持久化与恢复

**现状问题**：关闭终端后任务状态丢失，无法断点续传。

**期望功能**：
```bash
# 保存当前会话状态
/session save "重构认证模块-进行中"

# 查看保存的会话
/session list
# 输出:
# 1. 重构认证模块-进行中 (2小时前, 5/12 TODO完成)
# 2. API文档编写 (昨天, 已完成)

# 恢复会话
/session resume 1
# 自动恢复: TODO列表、文件修改记录、对话上下文摘要
```
