# 多 Agent 协作协议

## 概述

多 Agent 协作协议是 oh-my-claude 的核心特性之一，允许不同的 Agent 之间进行无缝协作和信息传递。该协议基于 `@agent` 调用语法，实现了类似 oh-my-opencode 的协作模式。

## 协作流程

### 1. 调用检测

当用户输入包含 `@agent` 语法时，`agent-collaboration.sh` hook 会：

1. 检测所有 Agent 调用
2. 解析 Agent 名称和任务描述
3. 标准化 Agent 名称映射
4. 生成协作协议消息

### 2. 协议消息格式

```markdown
---
【多 Agent 协作】Agent 调用
协作ID: collab_1640995200_zhuge
目标Agent: zhuge
任务描述: 请分析这个系统的架构需求
调用时间: 2023-12-31 12:00:00
状态: 待处理
---

请 @zhuge 处理以下任务：
请分析这个系统的架构需求

---
【协作协议】请按以下格式响应：
✅ 接受任务 - 开始处理
🔄 处理中 - [进度百分比] [当前步骤]
❌ 无法处理 - [原因说明]
✅ 任务完成 - [结果摘要]
---
```

### 3. Agent 响应格式

被调用的 Agent 应该按以下格式响应：

**接受任务：**
```markdown
✅ 接受任务 - 开始处理
```

**处理中汇报：**
```markdown
🔄 处理中 - 60% 已完成需求分析，正在制定架构方案
```

**无法处理：**
```markdown
❌ 无法处理 - 这个任务需要数据库设计知识，我建议调用 @cangjie
```

**任务完成：**
```markdown
✅ 任务完成 - 已完成系统架构设计，包含3层架构和API规范
```

## 状态管理

### 协作会话跟踪

每次 Agent 调用都会创建一个协作会话：

```json
{
  "id": "collab_1640995200_zhuge",
  "timestamp": "2023-12-31T12:00:00.000Z",
  "agents": ["zhuge"],
  "task": {
    "description": "请分析这个系统的架构需求",
    "status": "active"
  },
  "messages": [],
  "context": {}
}
```

### 协作历史记录

所有协作活动都会记录在 `~/.oh-my-claude/logs/agent-collaboration.log`：

```
[2023-12-31 12:00:00] 检测到 Agent 调用: zhuge 请分析这个系统的架构需求
[2023-12-31 12:00:01] 解析 Agent 调用: zhuge -> '请分析这个系统的架构需求'
[2023-12-31 12:05:00] 任务完成: 已完成系统架构设计
```

## 高级协作模式

### 多 Agent 同时调用

```markdown
@zhuge 请分析架构需求
@luban 请准备技术方案
@wukong 请探索现有代码
```

### 协作链式调用

Agent 可以在处理过程中调用其他 Agent：

```markdown
🔄 处理中 - 50% 架构分析完成，需要技术细节

@luban 请根据这个架构设计实现用户模块
@cangjie 请设计数据库结构
```

### 协作状态同步

```markdown
---
【愚公】多 Agent 协作状态同步
活跃任务: 3个
├── @zhuge: 架构设计 (80% 完成)
├── @luban: 用户模块实现 (45% 完成)
└── @cangjie: 数据库设计 (90% 完成)
总体进度: 72%
---
```

## 错误处理和重试

### 自动重试机制

- Agent 无响应：自动重试 3 次
- 处理超时：根据任务复杂度设置超时时间
- 处理失败：记录错误原因，提供降级方案

### 降级策略

1. **Agent 不可用**：尝试调用功能相近的 Agent
2. **任务复杂度过高**：分解为更小的子任务
3. **资源不足**：排队等待或建议手动处理

## 性能优化

### 上下文压缩

- 自动检测重复信息
- 生成摘要保留关键内容
- 智能清理过期上下文

### 并行处理

- 支持多个 Agent 同时工作
- 协调资源分配避免冲突
- 实时进度同步

### 缓存机制

- 缓存 Agent 响应结果
- 重用相似任务的解决方案
- 维护知识库加速处理

## 监控和分析

### 协作指标

- **响应时间**：Agent 接受任务到完成的时间
- **协作效率**：多 Agent 协作 vs 单 Agent 处理的效率对比
- **成功率**：任务完成率和质量评分
- **资源利用**：各 Agent 的工作负载分布

### 日志分析

```bash
# 查看协作日志
tail -f ~/.oh-my-claude/logs/agent-collaboration.log

# 分析协作模式
grep "协作ID:" ~/.oh-my-claude/logs/agent-collaboration.log | sort | uniq -c
```

## 最佳实践

### 任务分配原则

1. **专业对口**：根据 Agent 专长分配任务
2. **负载均衡**：避免单个 Agent 过载
3. **依赖管理**：正确处理任务间的依赖关系

### 协作 etiquette

1. **清晰描述**：任务描述要具体明确
2. **及时响应**：收到调用后及时确认
3. **进度汇报**：定期汇报处理进度
4. **结果总结**：完成时提供清晰的总结

### 故障排除

1. **调用无响应**：检查 Agent 名称拼写
2. **协作卡住**：查看日志分析阻塞原因
3. **质量不佳**：提供更详细的任务描述

## 扩展开发

### 添加新 Agent

1. 在 `agents/` 创建 Agent 定义文件
2. 更新名称映射表
3. 测试协作调用功能

### 自定义协作协议

1. 修改 `agent-collaboration.sh` 脚本
2. 更新响应格式规范
3. 扩展状态管理逻辑

### 集成外部工具

1. 在 hook 脚本中添加工具调用
2. 处理工具输出格式化
3. 实现错误处理和重试
